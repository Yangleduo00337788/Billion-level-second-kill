## 二、登录流程图

```
用户发起登录请求
    │
    ▼
┌─────────────────┐
│  限流检查        │ ← Redis滑动窗口
└────────┬────────┘
         │ 通过
         ▼
┌─────────────────┐
│  风控检查        │ ← IP/设备指纹/行为分析
└────────┬────────┘
         │ 通过
         ▼
┌─────────────────┐
│  黑名单检查      │ ← Redis Bloom Filter
└────────┬────────┘
         │ 通过
         ▼
┌─────────────────┐
│  凭证验证        │ ← 密码/OAuth/短信验证码
└────────┬────────┘
         │ 通过
         ▼
┌─────────────────┐
│  多端登录检查    │ ← Redis设备会话管理
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  生成Token       │ ← JWT + RefreshToken
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  写入Redis会话   │ ← Token绑定设备信息
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  返回登录结果    │ ← AccessToken + RefreshToken
└─────────────────┘
```

## 三、JWT设计方案

### 3.1 Token结构

```
AccessToken:
- 有效期: 2小时
- 包含: userId, username, roles, permissions, deviceId, sessionId
- 用途: 接口鉴权

RefreshToken:
- 有效期: 30天
- 包含: userId, deviceId, sessionId
- 用途: Token续期
```

### 3.2 Token续期机制

```
┌──────────────┐     ┌──────────────┐
│ AccessToken  │────▶│ 即将过期检查  │
│ (2小时)      │     │ (<15分钟)     │
└──────────────┘     └──────┬───────┘
                            │ 是
                            ▼
                     ┌──────────────┐     ┌──────────────┐
                     │RefreshToken  │────▶│ 验证有效性    │
                     │ (30天)       │     │ Redis检查     │
                     └──────────────┘     └──────┬───────┘
                                                │ 有效
                                                ▼
                                         ┌──────────────┐
                                         │ 生成新Token  │
                                         │ 更新Redis    │
                                         └──────────────┘
```

### 3.3 JWT Payload设计

```json
{
  "sub": "userId",
  "username": "用户名",
  "roles": ["admin", "user"],
  "permissions": ["user:view", "user:edit"],
  "deviceId": "设备唯一标识",
  "sessionId": "会话ID",
  "loginTime": "登录时间戳",
  "ip": "登录IP",
  "jti": "Token唯一标识",
  "exp": "过期时间"
}
```

## 四、Redis存储结构

### 4.1 Token存储

```
key: user:token:access:{userId}:{deviceId}
value: AccessToken字符串
expire: 2小时

key: user:token:refresh:{userId}:{deviceId}
value: RefreshToken字符串
expire: 30天
```

### 4.2 用户会话管理

```
key: user:session:{sessionId}
value: Hash {
  userId, deviceId, deviceType, ip, loginTime, lastActiveTime
}
expire: 30天
```

### 4.3 设备管理

```
key: user:devices:{userId}
value: Set {deviceId1, deviceId2, ...}
expire: 90天
```

### 4.4 登录失败计数

```
key: user:login:fail:count:{ip}
value: 失败次数
expire: 15分钟

key: user:login:fail:count:{userId}
value: 失败次数
expire: 15分钟
```

### 4.5 黑名单

```
key: user:blacklist:ip
value: Set {ip1, ip2, ...}
expire: 永久

key: user:blacklist:user
value: Set {userId1, userId2, ...}
expire: 永久

key: user:blacklist:device
value: Set {deviceId1, deviceId2, ...}
expire: 永久
```

### 4.6 用户画像

```
key: user:profile:{userId}
value: Hash {
  age, gender, city, tags, interests, loginCount, lastLoginTime
}
expire: 7天
```

## 五、风控设计

### 5.1 IP风控

```
规则:
- 单IP登录失败>5次: 限制15分钟
- 单IP登录失败>10次: 封禁24小时
- 单IP高频请求: 触发验证码
- 异地登录: 二次验证
```

### 5.2 设备指纹

```
采集信息:
- UserAgent
- 屏幕分辨率
- 语言设置
- 时区
- Canvas指纹
- WebGL指纹
- 字体列表

生成算法:
MD5(UserAgent + 分辨率 + 语言 + 时区 + Canvas指纹)
```

### 5.3 行为风控

```
规则:
- 登录频率异常
- 时间段异常
- 地理位置跳跃
- 设备更换频繁
- 操作模式异常
```

### 5.4 风控评分

```
风险评分 = IP风险(40%) + 设备风险(30%) + 行为风险(20%) + 时间风险(10%)

评分阈值:
- 0-30: 低风险，正常登录
- 31-60: 中风险，验证码
- 61-80: 高风险，短信验证
- 81-100: 极高风险，拒绝登录
```

## 六、多端登录控制

### 6.1 设备类型

```
- WEB: 网页端
- APP_IOS: iOS端
- APP_ANDROID: Android端
- MINI_PROGRAM: 小程序
- PC_CLIENT: PC客户端
```

### 6.2 控制策略

```
- 允许同类型设备单点登录
- 不同类型设备可同时在线
- 新设备登录踢出旧设备(可配置)
- 最多同时在线设备数限制(默认5个)
```

用户 ──多对多──> 角色 ──多对多──> 权限

### 7.2 权限类型

## 八、高并发优化方案

### 8.1 缓存策略

```
- 用户信息: Redis缓存，2小时过期
- 权限信息: 本地缓存 + Redis二级缓存
- Token验证: Redis直接验证，不查DB
- 黑名单: Bloom Filter + Redis Set
```

### 8.2 限流方案

```
- 登录接口: Redis滑动窗口限流，100次/分钟/IP
- Token刷新: 令牌桶限流，50次/分钟/用户
- 注册接口: 固定窗口限流，10次/分钟/IP
```

### 8.3 异步处理

```
- 登录日志: 异步写入
- 用户画像更新: 消息队列异步处理
- 风控数据收集: Kafka异步处理
```

### 8.4 数据库优化

```
- 读写分离
- 用户表按userId分库分表
- 热点用户数据预加载
- 批量操作优化
```

### 8.5 并发控制

```
- Token续期: Redis分布式锁
- 登录失败计数: Redis原子操作
- 设备管理: Redis Lua脚本保证原子性
```
